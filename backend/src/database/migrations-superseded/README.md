# Superseded migrations — not loaded, kept for reference

These 61 files were the hand-written migration chain until 2026-09-03. **Nothing
loads them.** The application and the TypeORM CLI read only
`src/database/migrations/` (`app.module.ts`, `data-source.ts`), and the jest
portability spec skips this folder.

## Why they were retired

`npm run db:verify` ran the chain on a real Postgres for the first time and found:

1. The chain had **never executed anywhere**. Development is SQLite with
   `synchronize: true`, the e2e suite forces SQLite in memory, and CI never
   connected to the Postgres service it provisions. The first place it would
   have run was a production database.
2. It **could not run**: entities and migrations used SQLite spellings
   (`datetime`, `blob`, `double`) that Postgres rejects at DataSource
   initialisation, the 13 "foundational" `Create*Schema` migrations carried
   later timestamps than the migrations depending on their tables, one index
   was created twice, and the optional pgvector migration aborted the whole
   chain on any Postgres without the extension.
3. Once all of that was fixed (the versions here include those fixes) the
   schema it produced still **differed from the entities by 1,498 statements**
   — uuid vs varchar(36) ids, enum vs varchar, 261 index names, missing
   columns.

The entities are what the application has always actually run against, so
the chain was rebuilt from them: `InitialSchema` in `../migrations/` is
generated by TypeORM from the entities, and `db:verify` proves on every
`production:check` and CI run that the chain applies from an empty database
and reproduces the entity schema exactly.

## If a database somewhere did record these names

No such database is known. If one exists, its `migrations` table lists names
from this folder; bring it forward with `migration:run --fake` for the baseline
after reconciling the schema by hand — do not re-add these files to the active
folder.

This folder can be deleted in one commit once nobody needs to compare against
it; git history keeps it either way.
