Fixed with a proper per-arrival merge (mergeEmsArrivalHydration) that preserves locally-tracked progression fields while still taking fresh field values (chief complaint, vitals, etc.) from the backend, and correctly drops arrivals the backend no longer listsConfirmed — this had been silently breaking the offload timer under normal multi-user load since before this audit found it.

Combined with the fix above, the real remaining gap is durability, not fakery: the offload clock lives entirely in the browser tab (now correctly preserved across real-time updates, but still not backed by a persistent server-side EMS-arrival entity), so it still won't survive a hard page reload or stay consistent across simultaneous workstations without a fresh hydration re-establishing it from local memory that may no longer exist.
