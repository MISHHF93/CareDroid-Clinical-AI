## Unassigned Assets And Gap Analysis

No unassigned assets were found in the generated commercial graph. Every canonical platform asset resolves to at least one department, service line, asset pack, product, subscription plan, role, and organization type.

## Commercialization Recommendations

- Treat `SEED_PLATFORM_ASSETS` as the canonical SaaS asset registry and stop introducing launchable capabilities that bypass pack, product, role, department, service line, organization, and plan fields.
- Keep frontend tool and route inventories as implementation evidence, not commercial ownership sources. Runtime visibility should continue to flow through entitlement-filtered platform APIs.
- Use the asset pack matrix as the implementation backlog for tenant onboarding templates. New customers should configure products and packs, not request code changes.
- Keep `Core Platform Foundation` and `AI Workflow Automation Suite` as foundation product owners for shared platform and AI workflow packs so every asset has a commercial owner.
- Require new assets to pass the same coverage checks represented here before release: department, service line, pack, product, plan, role, organization type, governance owner, lifecycle, and entitlement behavior.

## Revenue Architecture

CareDroid now resolves revenue through:

```text
Organization -> Subscription Plan -> Product -> Asset Pack -> Asset -> Role -> Outcome
```

This answers which organization buys which product, which department uses it, which roles receive access, which outcomes the pack is sold against, and which subscription plan entitles the capability.

## Migration Priorities

1. Keep all launch surfaces mapped to `SEED_PLATFORM_ASSETS` before adding new UI routes or backend executors.
2. Move customer onboarding from hand-edited code paths to selected organization type, plan, products, and packs.
3. Add CI checks that fail when any asset lacks department, service line, pack, product, plan, role, or organization mapping.
4. Expand buyer/outcome metadata at the product and pack level for sales collateral and implementation scoping.
5. Use usage metering and customer success dashboards to validate actual adoption by department and plan.
