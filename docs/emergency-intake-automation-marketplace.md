# Emergency Intake Automation Marketplace

## Goal

Package intake automations as a sellable Emergency Workspace product category.

The marketplace should organize intake capabilities into clear modules that can be enabled, bundled, and mapped to SaaS tiers.

## Modules

The Emergency Intake Automation Marketplace should package:

- Smart Intake
- OCR Intake
- Identity Resolution
- Patient Snapshot
- Medication Capture
- Allergy Capture
- Voice Intake
- Multi-Language Intake

## Product Category

Intake automation should become a distinct product category focused on reducing registration burden, accelerating early patient context, improving accessibility, and making door-to-triage operations measurable.

The category should be positioned around:

- Faster registration.
- Lower manual data entry.
- Better intake completeness.
- Earlier clinical context visibility.
- Reduced duplicate record risk.
- More accessible intake paths.
- Clear governance and review controls.

## SaaS Tier Mapping

Map marketplace modules to SaaS tiers:

| Module | Core | Pro | Enterprise |
| --- | --- | --- | --- |
| Smart Intake | Included | Included | Included |
| OCR Intake | Limited | Included | Included |
| Identity Resolution | Basic | Included | Advanced |
| Patient Snapshot | Basic | Included | Advanced |
| Medication Capture | Limited | Included | Advanced |
| Allergy Capture | Included | Included | Included |
| Voice Intake | Not included | Add-on | Included |
| Multi-Language Intake | Not included | Add-on | Included |

Core should cover foundational intake assistance and critical risk capture. Pro should expand into document processing, richer patient context, medication capture, and optional accessibility add-ons. Enterprise should include advanced identity resolution, advanced patient snapshots, advanced medication capture, voice intake, and multi-language intake for larger operational deployments.

## Marketplace Behavior

The marketplace should allow tenants to:

- View available intake automation modules.
- See which modules are active for their SaaS tier.
- Understand upgrade paths for locked modules.
- Configure enabled modules according to role and governance policy.
- Track usage and value signals for each module.

## Packaging Rules

Each module should define:

- Product description.
- SaaS tier availability.
- Required dependencies.
- Required review or confirmation controls.
- Key workflow routes.
- Usage metrics.
- Upgrade messaging.

No module should bypass patient confirmation, clinician review, audit logging, source attribution, or correction workflow requirements where those controls apply.

## Acceptance

The Emergency Intake Automation Marketplace is ready when:

- Smart Intake, OCR Intake, Identity Resolution, Patient Snapshot, Medication Capture, Allergy Capture, Voice Intake, and Multi-Language Intake are packaged as modules.
- Modules are mapped to SaaS tiers.
- Tenants can understand which intake automations are included, available as add-ons, or unlocked through upgrade.
- Intake becomes a sellable product category.
