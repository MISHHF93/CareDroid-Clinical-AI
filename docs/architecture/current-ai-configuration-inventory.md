## Key Findings

- Active ED Copilot remains the primary AI interaction surface in the Emergency OS UI; AI Governance is now mounted as a supervision and compliance surface, not a new clinical AI feature.
- The backend still mounts broad legacy AI, RAG, AI gateway, medical control plane, and tool-calling modules because `ChatService` depends on them.
- No frontend provider API key is required for active AI. Browser AI calls now route through backend Emergency OS endpoints.
- The only provider key in runtime code is `ANTHROPIC_API_KEY` on the backend/shared client side.
- RAG/Pinecone are optional backend modules and should be treated as future/legacy until narrowed to Emergency OS.
- Enterprise AI governance is embedded through `AIConfigRegistry`, `PromptTemplateRegistry`, `AISafetyRules`, `AIGovernanceService`, always-mounted Nest `/api/v1/governance/*` routes, compatibility `/api/emergency/governance/*` routes, and the `/ai-governance` dashboard.
- Current audit persistence is intentionally an in-memory auditable fixture repository for local wiring; production deployment still needs durable TypeORM/audit-log storage for AI interaction retention.
- Verification target: `npx ts-node scripts/verify-ai-config.ts` from `backend/` validates 10 AI services and 3 prompt templates.
